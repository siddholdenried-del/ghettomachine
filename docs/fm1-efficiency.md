# FM-1 audio efficiency: what to try next

Keep the current BongDrums and BongSynth voices, including the Felucca-based synth, waveshaping, velocity response and natural cymbal tails. Improve how we calculate and schedule the same sounds before simplifying the sounds themselves. The target is one drum track and three synth tracks feeding shared BongVerb and BongDelay sends and the BongMaster output chain.

## What we know

| Evidence | What it proves |
| --- | --- |
| An earlier hardware build, `C06FC63C`, logged a 4.615 ms worst render block against a 5.805 ms deadline, with no late blocks, overruns or xruns. The run logged **19 voice reductions**. | That specific build stayed on time with its protection active. It is not a full-voice pass or a timing result for the current engine. |

Neither host nor browser time predicts FM-1 deadline performance. |
| The audited code already uses reciprocal math in Perc, avoids a separate drum-bus clearing/scaling pass, and specializes metal rendering per lane. | Keep those changes. Profile the remaining work instead of redoing them. |
| An isolated C test compared 231,040 cached and uncached LFO 2 phase increments bit for bit across 60–240 BPM, all 128 rate positions, startup and tempo changes. | Caching the calculation can preserve the arithmetic. It has not been integrated or timed on the FM-1. |

## Optimization order

1. **Capture the baseline before changing DSP.** Use the exact firmware build under test and a fixed dense song. Measure the whole callback, not the average meter. Capture both cores with the same block ID, plus dispatch, wait and fallback. The cores overlap: adding their percentages does not tell us whether the callback fits. Compare CPU 2 policies at equal voice counts; disabling the second core can also lower the voice pool, which would invalidate a straight time comparison.
2. **Cache LFO 2’s tempo divisions.** In [synth.c](https://github.com/siddholdenried-del/ghettomachine/blob/337dcddf7e13fee51fdd909435b0ab866d459bc7/app/dsp/synth.c#L1156-L1177), every active, synced voice repeats the same tempo/division arithmetic on the 32-sample control tick. Precompute the 12 increments at the 120 BPM default and on tempo changes, preserving floating-point operation order. Keep the live per-voice rate modulation, clamp and division lookup. Publish the cache before either core renders with it; check cold start, reboot, project reload, tempo changes during held notes and the simulator's direct engine entry points. Test NOTE SYNC, FREE SYNC, rate feedback, presets and locks. Compare deterministic WAVs before measuring device time.
3. **Only then test skipping unused work.** If the profiler still points at LFO 2, consider skipping waveform evaluation when it has no consumer. Do not skip phase, fade or random updates that a late route or scope opening would reveal. Verify sample-and-hold, smooth random, matrix activity meters, and opening the scope or enabling a route halfway through a held note. If scheduling, drum tails, or the shared FX dominate the worst blocks instead, go there first. Do not turn silence thresholds up or shrink the voice pool just to improve the meter.
4. **Check memory as well as time.** For each candidate, diff the hardware linker map and record static RAM, RAM-resident code, per-core stack and audio-pool high-water. Check concurrently enabled features, particularly shared delay, sampling and performance effects. A speedup that duplicates a large buffer or squeezes out stack margin is not free.

## Ship/no-ship test

- **Use matched fixtures:** same project and MIDI events, presets, gains, seeds, voice counts, USB/MIDI state and sends. Include a dense four-track groove with long cymbal tails, three sustained synth parts, both sends and master; also test clip or kit changes, Fill, live edits and FX throws. Capture the current and candidate builds on the same FM-1, after warmup, in at least three two-minute runs per fixture.
- **Measure every callback:** record p50, p95, p99, worst and deadline misses. At 256 frames / 44.1 kHz the deadline is **5.805 ms**. Capture a complete block trace or bounded on-device histogram with an exact max and miss count. USB status polls can count counter deltas, not establish p99. Measure the recorder's overhead. Log voice reductions and drum-tail shedding separately and compare protection off and on.
- **Acceptance:** zero missed blocks and no unexpected note or tail loss, with protection off or verified not to have intervened. Aim for **4.93 ms full-callback p99 or faster**, with **4.64 ms** as the tighter target on the matched dense set. Every callback still has to meet 5.805 ms. The earlier **2.90 ms** target was a budget goal for the four instrument tracks, not a measured full-callback target and not the hardware deadline.
- **Prove the sound:** sample-for-sample comparison for changes claimed transparent. If a change intentionally affects sound, use a level-matched blind A/B on kick transient, pitched tails, hat/cymbal decay, modulation, and stereo FX. Include the dense pattern: a clean solo tail does not prove it survives under load.
